# Linking a field note to a saved grower cycle

The pure resolver uses the existing whole crop-plan projection. It checks a grower's explicit planting, bed, proposal ordinal and scope against the current saved book and geometry. The persistent planting ID selects the row. A repeated proposal ordinal can never select a different row. Duplicate IDs, overlapping reservations and stale or absent geometry keep the link on hold. The returned link contains identity only. Planned dates and quantities cannot become observations by passing through the resolver. A mapped scope ID encodes the site coordinates. Keep the link in the private journal context and exclude the ID from URLs, diagnostics and exports unless specifically authorized.

The journal remains the record of what happened. Before writing, the confirmation flow must establish the current actor and selected workspace, obtain the canonical book and source through `loadGrowerOperationsSources`, and verify that the original admitted sources still match with `checkGrowerOperationsCurrent`. Immediately before the synchronous journal save, it must check `isGrowerOperationsCurrent` and the journal's own actor and revision. A changed or unavailable link holds the form. The grower can retry, cancel or explicitly choose an unlinked note. The observed date comes from the journal form. A planning date, task tick or query parameter cannot supply it.

`readJournalLinkWriteReceipt` and `journalLinkWriteReceiptMatches` provide an opaque comparison of current browser storage, actor, sample flag and journal bytes. An absent journal and an empty array are distinct. Nonempty values that the existing writer cannot represent byte-for-byte, and rows that normalization would alter or discard, are held for the linked-note path. The receipt is not a lock and cannot prove that an intervening account or sample transition never happened. The confirmation controller must retain its own form and actor lifetime guard.

The journal store can retain a private link marker and append one explicitly dated note against the original receipt. The append holds if the journal is full or has changed. It keeps earlier rows and photos, consumes the receipt before attempting one write, and reports an uncertain result without retrying. A structurally valid stored link is only a hint to resolve again against the current authorized book. Ordinary journal reads and edits retain even a malformed marker, and existing CSV and printable copies omit the private linkage.

The append requires a synchronous current-source guard from the live confirmation controller after that controller has refreshed its original source. The controller is still pending. Neither an imported marker nor this store function gives a sharing or consent grant.


The live write needs one journal authority for ordinary saves, deletes and linked appends. An independent in-memory reproduction saved a linked note, then used the ordinary whole-book saver from a stale tab snapshot and erased the link. A readback proves only what the writer observed, and an append-only lock would leave the older saver able to overwrite it. A deployed older bundle can also strip the marker after reload because its v1 normalizer does not recognize the field. Reuse the crop-plan cutover's account-scoped writer and older-session safeguards where the journal contract fits. Hold the linked form until the journal writer boundary and stale-client recovery are verified. A note whose edited bed conflicts with its retained marker must show the link as held. Include guest-to-account migration in the writer inventory. Imported links are shape hints only and must be resolved under the receiving account’s own book.


The cutover prerequisite can initialize a separate account-scoped v2 journal under the existing Web Locks pattern. It validates and copies the v1 raw journal, retains the original key, and stores a SHA-256 comparison of the exact legacy string in the new envelope. Later writes to v1 are reported as divergence without replacing v2. Missing locks, quota or unreadable state hold the operation. Guest transfer and the built-in sample remain separate admission cases. This prerequisite has no production caller. Canonical ordinary edits, deletes and linked writes still need to use the same authority, and divergence needs a grower-visible recovery flow.
