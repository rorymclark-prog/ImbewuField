# Checked grower dates in one calendar file

The dated-work panel previously downloaded one event per click. Its new bulk action prepares one file for the represented, checked grower cycles, including checklist items already marked done. Month-only catalogue tasks retain their separate export path. Neither export records observed work, stock, production or a free-bed confirmation.

The bulk builder reuses the existing single-task event writer, opaque identities, canonical UTC days, exclusive next-day end, escaping and UTF8 folding. Missing, invalid, duplicate or unrepresentable members hold the entire file. Held source measurements or cycles also hold the bulk action; existing individual actions remain available. Calendar dates remain the grower's estimates, including their planned end and availability boundaries. No alarms or recurrence are invented.

DEMO files, calendar names and every event are labelled. Demo event identities have a separate prefix so importing them cannot replace real events with the same supplied task identity. Normal bulk event identities match the existing individual export. Private journal/scope links never enter the event payload.

The async action retains its original source, account/sample context and mounted operation. A callback or sample property changing away and back permanently withdraws the old request. Delivery rechecks currentness through serialization and browser preparation, immediately before clicking the download link, then cleans up the resources it created. No new ledger or persistence schema is introduced.
