# Saved planned nursery batch references

Market gardeners can check saved own-input transplant cycles, enter a variety/cultivar, seed-lot reference and raising-batch reference for each persistent planting, save all touched entries, and reuse the existing dated nursery resource review and worksheets. These are grower-entered planned references. They do not verify seed identity, record actual sowing, create seed or seedling inventory, approve plant health, or grant sharing consent.

## Canonical source and counts

`Planting.variety` remains the single variety authority. The optional `nurseryBatchReference` attachment binds seed-lot/raising-batch labels to the persistent planting, original assessment and scope. Repeated cycle ordinals are not identities. Proposed cycles cannot receive a durable saved reference. Existing whole-book projection and measurement/assessment checks remain authoritative.

The original preparation grouping and all plant/seed/container/surface calculations remain unchanged. Same-crop, same-date groups show distinct member references; matching crop names or labels do not establish interchangeable seed lots. Missing or malformed saved reference metadata is displayed as needing review and is not silently replaced by blank fields. Optional clearing is an explicit edit, with unknown metadata retained.

## Save and readback

Private hook bindings retain original rows, checked source, actor/sample identity and saved-book token. The actual parent uses canonical raw-read/write-admission, lossless candidate and actor/base/token guards. A revocation-only callback carries the original source boundary through the existing storage writer checks; it cannot grant permission or bypass the existing account, lease or candidate rules.

A successful stored-byte receipt is followed by an independently admitted exact readback. Only its private, once-consumed acknowledgement may cross the parent's own rerender. The editor checks the installed saved view before clearing touched inputs or reporting saved. Stale callbacks, altered sources, account/sample transitions, ambiguous writes and changed readbacks cannot become success.

Two independent review findings were reproduced and repaired: nested undefined attachment properties disappearing during sample JSON projection, and a source-change event during saver storage reads arriving too late to prevent a physical write. The original nested probe and the source probe with faithful forwarding of the new saver options each pass. An obsolete one-argument instrumentation wrapper that discarded those options is preserved separately as a fixture limitation.
