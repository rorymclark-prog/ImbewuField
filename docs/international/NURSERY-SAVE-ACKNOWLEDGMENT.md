# Nursery save acknowledgment

Both route-owned nursery panels now submit an opaque request captured from their
original actor, sample session, site/scope, nursery settings and exact admitted
crop-plan base. A later props object, Boolean, fingerprint or forged brand cannot
confirm a save. The two-argument harvest-target/legacy Boolean API is unchanged;
it is not a nursery UI acknowledgment.

The parent retains the existing single namespace merge. It reads a fresh admitted
book, preserves current foreign rows, and holds changed own-site rows, held
claims, source issues or lossy evidence. The original admission remains required
through a legitimate foreign-only rebase. No second nursery store or schema
normalizer was introduced.

`nursery-save-receipt` owns the actual final canonical write and readback. It
checks the original request and intended own-site payload before writing, then
requires the returned token, current lease/admission and exact admitted saved
book to agree. The parent installs that real confirmed book/base. Only the
private request-bound result can clear the same submitted draft, once. Its own
successful base replacement does not invalidate its acknowledgment. Equivalent
contexts must share the same private authority and original base, rather than
merely equal public fields.

The descriptor-safe source key records original data identity, including held
inputs and source issues; it does not replace the existing semantic nursery
fingerprint. A confirmed rebase exposes only its proof-bound actual readback
source key, so newer foreign rows are not confused with the submitted old prop.
Actor/sample lifecycle events, site/scope changes, cleanup and revoked leases
invalidate retained authority, including identity changes that return to their
starting values. Configured missing authentication is distinct from a genuine
guest; backendless device planning remains supported.

After a write attempt, false, an exception or mismatched readback is unconfirmed.
It cannot establish rollback or unchanged storage and does not permit automatic
retry. Sample confirmation describes the same in-memory sample only, with no
claim of device persistence. Optional refresh notifications are already isolated
by the canonical writer and do not undo a genuine receipt.

Verification uses actual extracted parent handlers/effects, real mounted React
lifecycles, the canonical initializer/lease, raw readers, saver and admission
helpers in isolated memory. Controls include initial absent context followed by
asynchronous readiness, same-bytes lease replacement, readback mismatch, partial
write exceptions, foreign rebase, replay/forgery, dirty/stale sources, unsafe
accessors, legacy settlement and sample/device separation. No real farmer data
is touched. Browser/account release checks remain required; no browser appearance
or production persistence claim follows from these tests.
