# Closed nursery and harvest save acknowledgments

The existing nursery receipt module now owns two private purposes: `nursery` and
`harvestTargets`. Existing nursery APIs remain compatible wrappers. Both share
one parent actor/sample/site/scope lifecycle authority, original admitted-base
proofs, request registry and actual canonical write/readback implementation.
Contexts and requests have distinct types; every stage also checks the private
purpose. Identical-looking public statuses or copied brands cannot cross fields.

Both actual harvest panels pass their context to a request-required target
producer through `onTargets` and `onSaveTargets`. Their existing scoped merge
remains the only namespace preparation authority. The old two-argument Boolean
API stays compatible for internal legacy callers, but a Boolean is not a nursery
or harvest acknowledgment. Catalogue direct edits and deletes no longer have a
separate route-owned Boolean bypass. Planner proposal acceptance is unchanged.

A valid raw sample exposed an existing target guard that treated JSON object
property insertion order as a foreign-data change. The two target comparisons
now reuse the descriptor-safe raw source key: every value, metadata field and
array position still matters, while object key order does not. Unreadable null
identities never compare equal. Nursery comparisons and canonical schemas are
unchanged; this is not sanitizer-based permission.

The helper confirms only the selected field's original own-site intent. A
candidate must retain every freshly loaded unrelated field and selected-field
foreign row; only the selected field and the existing update timestamp may
change. These are descriptor-safe evidence comparisons, not a second schema,
normalizer, namespace merger or store. Canonical admission still protects raw
absence, malformed rows, duplicates, metadata and legitimate legacy settlement.
A foreign-only rebase uses the existing parent merge and reports its actual
confirmed full-field source identity, including newer foreign rows.

Only the real saver plus matching admitted readback can produce confirmation.
Its original request remains verifiable after its own successful base replacement;
other dirty panel requests retain their inputs under a hold. Same-source context
reissues require the same private authority and original base. Actor/sample ABA,
site/scope changes, cleanup and revoked leases cannot lend a new grant. Sample
confirmation describes sample memory only. A possibly performed write that
returns false, throws or has changed readback remains unconfirmed, with no
rollback claim or automatic duplicate retry.

The bounded verification exercises actual route callbacks, shared parent
handlers/effects, the canonical initializer/lease, saver and readback in isolated
memory. Controls cover cross-purpose substitutions, collateral changes, retained
foreign data, ambiguous raw evidence, stale/dirty sources, cold asynchronous
context arrival, same-byte lease renewal, one actor observer, sample separation
and accessor rejection. Browser appearance/account release checks remain separate;
this contract makes no new crop timing, yield or agronomic claim.
