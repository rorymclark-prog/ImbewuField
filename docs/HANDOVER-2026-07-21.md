All three, every time, before you say anything is done. Not "looks right" — run them. I caught a

about a change's correctness — including your own — until you've either run it or worked through
the actual numbers/logic yourself.

## THE recurring bug — read this section twice

This file, and its siblings (`lib/producer-prompt.ts`, `lib/glossy-filters.ts`,
`lib/design-elements.ts`), have **more than one place that answers the same question** — "what is
this element called", "which sheet does this belong on", "which wizard step owns this shape". Each
one was added independently, by a different pass, at a different time. They agree today. They will
not agree tomorrow unless every new place that needs the answer **reuses the existing lookup**
instead of writing a new one.

Confirmed instances of this exact bug, found and fixed **today, in this one session**:
1. A ground-feature's AI-prompt-facing name diverged from its canvas/sheet name (three separate
   naming functions, only some of which checked the farmer's custom `z.name` first).
2. `lat < 0 → north` hemisphere assumption for solar geometry — hardcoded independently in
   `lib/sector.ts`, **three separate API route call sites**, and (found later, separately)
   `components/GeometryDesignStudio.tsx` — a fourth copy nobody remembered existed until it was
   specifically searched for.
3. A legend-row numbering scheme (`CIRCLED = ['①'...'⑨']`) capped at 9 glyphs while a sibling
   feature (terracing) independently added a 10th possible row — two energies both rendering as
   "⑨" on a real site.
4. Wind-direction text hardcoded as literal "NE"/"SW"/"NW" in a legend row's label string, instead
   of reading the same `fromLabel` field the map arrow itself uses — correct today only because
   exactly one regional wind table exists.
5. AI-illustration prompts (`lib/producer-prompt.ts`) gave the model texture vocabulary for
   buildings/driveways/lawn/veld — but not for paved/concrete ground, in **two separate prompt-
   building functions** that each independently list ground textures. A concrete slab next to a
   building had nowhere to go except "more roof."
6. A "which step owns this shape" answer (`ownedByCurrentStep`, `lib/glossy-filters.ts`) was
   nearly written a SECOND way — an early draft used `sheetForElement` (which output *sheet* an
   element prints on) instead of `CATEGORY_STEP` (which wizard *step* placed it) — different
   questions that happen to agree for most elements but disagree for four (raised bed, keyhole
   bed, herb spiral, tree basin: earthworks category, placed from the Water step, printed on the
   Planting sheet). Caught by an adversarial review before it shipped, not after.

**When you add a feature that needs to know "what is X called" or "what category/step/sheet does
X belong to": grep for the existing answer first.** Candidates, roughly in order of how likely
they are to already have what you need: `lib/glossy-filters.ts` (sheet/step/layer membership),
`lib/design-elements.ts` (`GROUND_FEATURES`, `CATEGORY_STEP`, `ELEMENTS_BY_ID`),
`components/design/DesignGlossy.tsx` (per-kind default label maps, searched as `LINE_NAME`/
similar), `components/design/DesignCanvas.tsx` (`LINE_KIND_LABEL`, mirrors DesignGlossy's copy
verbatim — check both if you touch either). If you're about to write a new `Record<Kind, string>`
or a new categorization switch, stop and check whether one already exists.
